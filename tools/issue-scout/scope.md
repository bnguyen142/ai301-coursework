## Where candidates come from

Any public repository. The sandbox is behind you; the field is now
all of GitHub, and your fit profile below is what keeps that
searchable. Start from repos in languages and tools you named there,
and let the profile steer where you search, not just how results are
ranked.

**Claims count again.** The Path Review house rule does not travel.
Out here a claim comment or an assignee is a stranger who got there
first, and you have no channel to coordinate with them. Read claim
signals exactly as the rubric's checks state them; do not carry the
classroom habit of claiming over someone.

**Claim upstream the moment you commit.** The rule cuts both ways:
the instant you decide to take an issue, say so on the issue itself
(a short comment: what you plan to do and roughly when). You are now
the claim signal someone else's skill will read. Deciding privately
and claiming later is how two strangers do the same work twice.

## Your fit profile

Python is my strength, and I also know basic C and C++. I know Android
development, and at work I operate in an AWS S3 kind of environment, along
with a lot of SQL. The rest I can learn. I want to grow to be a developer.

Tests are my strongest ground. Writing pytest tests, reading a failing one,
and working backwards from the failure to the cause is the part I am
genuinely good at. An issue whose expected behavior is stated plainly is
worth more to me than a tidy writeup with no way to tell when I am finished.

For my first project I am interested in tools I use every day, like Doom
Emacs, Omarchy and org. I like a repo that helps me stretch a little. Python
first, Omarchy if the bug is small.

I operate on Linux, so I want a bug that is easy to test in that
environment, with Docker if needed. I am looking for an active repo where
maintainers respond weekly. The project should allow AI usage, and if it has
AI requirements, they should be explained. If a repo has no AI rules written
down, keep it and I will ask the maintainer.

What I want to avoid is front end work, and a change that reaches across
several modules at once.
